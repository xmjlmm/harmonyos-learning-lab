# 环境与使用流程

## 每个工程独立打开

打开具体模块内含 build-profile.json5、oh-package.json5、hvigorfile.ts 的目录，不要把仓库根目录作为一个 HarmonyOS 应用导入。各项目配置文件没有跨工程路径引用，不需要将它们扁平化合并。

## SDK 与依赖

农场应用、状态示例和原型使用 6.0.0(20) SDK，账单示例使用 5.1.1(19) SDK。按工程现有配置选择对应 DevEco Studio/SDK；不强行统一版本。由 IDE 同步各目录依赖，重新生成本机缓存与 local.properties。仓库未附 Hvigor 命令行 wrapper，优先使用 IDE 的构建与运行入口。

## 签名与设备

原工程 signingConfigs 为空，需要在 IDE 中使用自己的开发签名并选定设备。农场与状态管理项目共享默认示例 bundleName，需要并行安装时自行配置独立包名及签名；本次保留原包名以避免改动应用身份。

分布式账单的跨设备同步需要受支持的设备、同一华为账号、相关分布式权限和网络条件，详见原始 Codelab 说明。单设备结构检查不能证明设备间同步已经验证。

## 推荐阅读顺序

1. 先阅读状态管理基础、扩展示例，比较父子状态绑定和主题共享。
2. 阅读分布式账单的数据库与视图模型边界。
3. 阅读智慧农场管理的 model、database、manager、components 与 pages。
4. 最后对照农场助手原型，了解它与主要课程应用的差异及未完成部分。
